# 仕訳帳 取込ルール

## 対象

- `/admin/work/journal-entries/import`

## 基本方針

取込前に対象年月と会社を確認する。
押した月や会社が分からないまま取り込まれるUIにしない。

## 取込中表示

件数が多いと止まって見えるため、取込中であることを画面に表示する。
二重送信を防ぐ。

## CSV・freeeデータ

freee由来の仕訳は、管理番号、発生日、勘定科目、部門、取引先、品目、摘要を重要条件として扱う。
不足している行をコード側で勝手に補完しない。

摘要（取引内容）等のセル内に改行を含む行が来ることがあるため、CSVパースは行単位のstr_getcsv()ではなく、
クォート内改行を正しく1レコードとして扱えるfgetcsv()ベースで行う（行分割方式に戻すと、改行を含む行の後続列が
すべてズレて取り込まれる）。

借方金額・貸方金額は、空欄は許容するが、非空かつ数値として解釈できない値は取込対象外とし、件数を画面に出す。
手動編集（金額欄）が数値以外を保存エラーで弾いているのに対し、取込だけ黙ってnullで保存する状態に戻さない。

## 取込の2段階化（アップロード時点では何も書き込まない）

以前はCSVアップロードした瞬間に、DBにまだ無い新規分を問答無用でINSERTしていた。取込前に
内容を確認したいという要望のため、アップロード時点では一切書き込まず、確認画面で内容
（新規追加候補件数・要確認の仕訳）を見せてから、別ボタン「この新規分を取り込む」を押した
時だけ実際にINSERTする2段階にした（2026-08-17）。

実装: `AccountingV2Controller::importJournalEntries()`（貯めるだけ）、
`AccountingV2Controller::applyNewJournalEntries()`（新規追加ボタンの実処理）

## 科目別照合（CSV合計とDB合計の突き合わせ）

確認画面で、科目ごとにCSV合計とDB合計（同じ会社・期間）を突き合わせて表示する。
仕訳No単位の突合だけでは、決算時に税理士が直接修正した場合などに気づけないための保険。

新規分がまだDBに書き込まれていない間は計算しない（新規分がDB側に無いので必ず不一致に
見えてしまうため）。「新規追加」ボタンを押してDBへ実際に書き込んだ後、確認画面を再表示する
タイミングで初めて計算・表示する。

突き合わせの対象からは、CSVに元々含まれない仕訳を除外する。除外しないと常に赤字（差額あり）に
なり、本当に確認すべき差額が埋もれる。

- 貸方勘定科目が `保険収入`/`自費収入`/`窓口収入` の行（取込処理自体がこの3科目を貸方から
  弾いている。旧AccessのfreeeCSV取込クエリと同じ条件）。ペアになる医療未収入金（借方）も
  同じ行として除外される。
- 店舗日報月次が作る経費仕訳（`journal_breakdown`が「年月+経費」で始まる、消耗品費/現金など）。
- 現金出納帳の仕訳（`vault_name`が入っている）。

実装: `AccountingV2Controller::buildJournalReconciliation()`

## 要確認の仕訳（既存とCSVの内容が違う場合）

同じ会社・取引日・仕訳Noの仕訳がDBに既にある場合、自動上書きせず確認画面に出す。ただし
内容が一字一句同じ（順不同で比較）なら確認対象に出さず、対象外件数に含める。一致判定は
`REVIEW_COMPARE_FIELDS`（借方/貸方科目・金額）だけで行い、摘要・部門名・税区分・メモ・
管理番号などは対象にしない（摘要は表記ゆれが普通にあり、部門名等はCSVの中身が同じでも
マッピング元マスタが後から変わると再取込のたびに「違う」判定になってしまうため）。

既存とCSVを別々の表で左右に並べると行がズレて比較しづらいため、1つの表にまとめ、項目ごとに
既存値・CSV値を隣り合わせで表示し、違う項目だけハイライトする。複合仕訳（1仕訳Noに複数行）は
DB保存順とCSVの行順が一致するとは限らないため、まず中身が完全一致する行同士を対応づけて
除外し、残った本当に中身が違う行だけを突き合わせて表示する。

実装: `AccountingV2Controller::buildReviewLinePairs()`

## 触らないこと

- 0円になった既存仕訳を取込処理で勝手に削除しない。
- 不明な入金名称や摘要を推測で除外しない。
- `報酬計算除外` の意味を取込時に変えない。
