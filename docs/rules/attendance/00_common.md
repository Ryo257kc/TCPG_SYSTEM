# 勤怠 共通ルール

## 目的

管理側の `admin/attendance` とスタッフ側の `/staff/attendance/monthly` で、同じ勤怠データを同じ考え方で表示・集計する。

画面は別でも、計算根拠、丸め、表示ルールは共通にする。

## 基本方針

- 管理側とスタッフ側で別々の計算式を作らない。
- スタッフポータル内の管理用勤怠画面も、勤怠集計は共通Serviceを使う。
- 勤怠の時間、日数、合計は共通Serviceまたは共通Builderで作る。
- 画面ごとの差は、操作ボタン、権限、表示項目の出し分けに限定する。
- 00:00は未入力の可能性があるため、実時間として扱う前に未入力判定を確認する。
- 確定済み勤怠を勝手に更新しない。
- 給与反映に使う値と画面表示の値がずれないようにする。

## 共通にするもの

- シフト所定時間
- 変更実績所定時間
- 実働時間
- 休憩時間
- 残業時間
- 深夜残業
- 休日出勤時間
- 出勤日数
- 欠勤日数
- 有休日数
- 有休残日数
- 遅刻早退時間
- 日額交通費
- 月合計
- 小数点表示
- 未入力の表示
- シフト所定と変更実績の差分色

## 画面ごとに分けるもの

- 管理側の確定、未確定ボタン
- 管理側の勤怠反映、勤怠一括反映
- 管理側のスタッフ選択
- スタッフ側の本人表示
- スタッフ側の申請、打刻、編集可能範囲
- スタッフ側の管理者向けページ

## 保存値と表示値

- DB保存値が正しい場合は、表示整形を確認する。
- 表示だけでDB値を変更しない。
- 給与反映に使う値は、画面で見える値と同じ根拠にする。
- 丸めは表示だけなのか、保存値なのかを分けて考える。

## 確定状態

- 勤怠確定はスタッフ、対象月単位で扱う。
- 未来月が勝手に確定済みにならないようにする。
- 給与確定ボタンの勤怠未確定判定は、勤怠確定状態と連動する。
- 確定済みの場合に更新できる処理、できない処理を明確にする。

## 給与との関係

- 勤怠反映は給与計算の勤怠値へつながる。
- 有休使用、有休残は勤怠反映側でそろえる。
- 再計算ボタン側に勤怠・有休反映を増やさない。
- 個別反映と一括反映で同じ結果にする。

## シフト画面

- `/staff/shift/change` と `/staff/shift/basic` は一覧内で編集・保存する。
- 個別編集ページへ遷移する旧GETルートは使わない。
- 保存POSTは一覧内フォームから呼ぶため、ルート名は `admin.shift.inline_update` / `admin.basic-shift.inline_update` を使う。
- シフト編集Bladeは `change.blade.php` と `basic.blade.php` を本体とする。
