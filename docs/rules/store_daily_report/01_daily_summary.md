# 月間日報 ルール

## 対象

- /staff/office/store_daily_report/daily_summary
- StoreDailyReportController::dailySummary()
- StoreDailyReportController::buildMonthlyWindowPrintData()

## 役割

月間日報は店舗日報の正しい売上集計を確認する正本。
売上一覧や売上PDFで別計算して合わせない。

## 集計元

- 患者別: dbo.T_患者名日報
- 先生別: dbo.T_先生別日報
- 経費: dbo.T_レジ詳細
- 差額: dbo.T_日報集計
- 月次保存値: dbo.mx_monthly_closings

## 基本式

通常分は patient.日付 で対象月を判定する。
回収分は patient.回収日 で対象月を判定し、patient.保険証 = 2 を対象にする。

- 自費: teacher.自費。ただし teacher.ch = 0。
- 保険負担: patient.レセ負担金（負担金ch = 0の分）＋ teacher.メニュー=返金の teacher.保険負担（現金返金分の調整）。
- その他/経費: T_レジ詳細。ただしチャージ金、物品販売、非表示ch は除外。
- 合計: 自費 + 保険負担 - その他。
- 差額: T_日報集計.差額。

### 返金（現金で窓口に返した分）

窓口で現金返金した場合、`T_先生別日報`にメニュー=「返金」・保険負担=マイナス値として記録されるが、
`T_患者名日報.レセ負担金`（受付側の値）は更新されない運用になっている。月間日報の保険負担計は
`patient.レセ負担金`が正本だが、この返金だけは先生別側にしか存在しないため、`メニュー=返金`の
行を別途SUMして加算（＝実質減算）する（2026-08-18、7/17さくらで保険負担が4,400円多く出る
不具合で発覚）。`T_日報集計.レジ`（レジ実額）はこの返金を差し引いた額と一致することを確認済み
（現金の払い戻しなので）。
返金以外でteacher.保険負担がマイナスの行（1,600件超）は対象にしない。それらは通常の請求調整で、
patient.レセ負担金側に既に反映されている前提。

## レセ負担金

月間日報入力で手入力するのは、さくら・ひなたのレセ負担金のみ。
月次済みは mx_monthly_closings の保存値を表示する。
保険負担は月間日報の集計値で、自動表示。手入力欄として扱わない。

## 日報印刷

/staff/office/store_daily_report/daily_summary/print の日報印刷は通常日報と修正日報で自費条件が違う。

- 通常日報: teacher.計算外 = 0。teacher.ch は見ない。
- 修正日報: teacher.計算外 = 0、teacher.ch = 0。
- 先生別外: 自費治療金、本日売上金、窓口合計からは除外しない。先生別集計から外すための条件。

2026/02/27 さくら鍼灸整骨院で一致確認済み。
- 通常日報 自費治療金: 59,610円
- 修正日報 自費治療金: 12,400円

### 保険証忘れは金額0でも修正日報から消さない

`dailySummaryPrint()`の修正日報(`print_mode=modified`)には、自費計・保険負担計・請求金額計が
全て0の行を除外するフィルタがあるが、保険証忘れ（patient.保険証 = 1 or 2）の行は保険証を
持ってきてもらうまで正常に金額が全部0のまま。これは「対応不要」ではなく「保険証待ちの
未対応」なので、金額0を理由に消してはいけない。保険証=1/2の行はこの金額0フィルタから除外する
（2026-08-18、秋富さんの行が修正日報から消える不具合で発覚）。
同じ「修正日報」という名前でも、`/daily_summary/detail`の「修正日報のみ」フィルタ（ch=0の行を
残す）とは別実装なので、修正日報関連のバグ調査では両方を確認すること。

## 施術者別月次

/staff/office/store_daily_report/daily_summary/monthly-print の施術者別日報集計は、店舗選択で絞らない。
その先生が対象月に担当した全店舗分を対象にし、日付・担当者IDで1日1行に集計する。

- 人数: 患者No の重複除外数。
- 自費: teacher.先生別外 = 0 の teacher.自費。
- 保険人数: teacher.請求金額 + teacher.保険負担 が 0 ではない行数。
- 保険負担: teacher.保険負担 の合計。
- 請求金額: teacher.請求金額 の合計。

2026/05 038 は店舗混在で対象にしつつ、日付単位で1行にまとめる。

## 日報集計一覧のサマリー編集

/staff/office/store_daily_report/daily_summary の一覧では、日報集計サマリーのうちレセコンとレジだけを直接編集できる。
保存時は dbo.T_日報集計 の対象行に対して、レセコン・レジのみ更新する。

- 月次処理済みの月は編集不可。
- 確定済み日報は、入金確認権限がない場合は保存不可。
- 先生別計、差額、銀行預入金額など他項目はこの一覧保存で更新しない。

## 日報詳細ヘッダー保存

/staff/office/store_daily_report/daily_summary/detail の上部ヘッダーで編集できるのは、レセコン・レジ・表紙表示欄のみ。
保存で更新するのは dbo.T_日報集計 のレセコン・レジ・備考（表紙表示欄）のみ。

- 来院人数、予約人数、院内人数、先生別計、差額、交通事故、銀行預入金額、カード、誤差チェックは表示専用にし、この保存では更新しない。
- 表紙表示欄は dbo.T_日報集計.備考 に保存する。

## 日報詳細の「戻る」ボタン

`url()->previous()` は使わない。編集保存（+追加・一括ch等）はPOST→同じdetailページへのGETリダイレクトなので、
保存後は`url()->previous()`が月間一覧ではなく詳細ページ自身のURLを指すようになり、「戻る」が反応しなくなる
（Laravelの`StartSession::storeCurrentUrl()`はGETリクエストの度に「前回のURL」を現在のURLで上書きするため、
POSTを挟んでも保存直前のGET＝詳細ページ自身のURLが「前回」として残ってしまう）。
`route('office.store_daily_report.daily_summary', ['target_month'=>$targetMonth, '日報集計店舗'=>$targetStore])`
のように、遷移元が確定しているページでは明示的にルートを組み立てる（2026-08-18修正）。
同じ理由で`resources/views/staff_portal/admin/shift/basic.blade.php`（基本シフト）の「戻る」も同時に修正済み。
