# 有給管理 管理画面ルール

## 対象

- `/admin/paid-leave`

## 基本方針

有給管理は付与、使用、喪失、残日数を管理する。
給与計算や勤怠画面で表示する有休残は、有給管理と一致すること。

## 対象者

スタッフマスタの有休対象チェックを考慮する。
有休対象外の人を選択肢に出さない。
退職や業務委託への変更があった場合、必要に応じて喪失処理で残日数を0にする。

## 喪失

喪失は履歴として残す。
過去の有給情報を削除して帳票や給与確認が追えなくなる状態にしない。

## 消滅日数（サマリーの見込み計算）

有休は付与から2年で消滅する。そのため残日数のうち直近1回分の付与だけは保護され、
それを超える分は次の消滅処理で消える。
サマリーの「消滅日数」は `max(0, 残日数 - 直近の付与数)` で計算する
（今回新たに付与される日数を足さなくても、上限＝直近付与＋今回付与との比較と数式上同じになる）。
Access時代もこの見込み計算をサマリーに出しながら、勤続年数が短く付与数が20日未満の人でも
消滅日数を間違えないよう確認していた。

各行に入っている`lost_num`（付与実績行の消滅数）は、その回の付与を処理した時点で
手入力された実績値であり、この見込み計算とは別物。一致しないことがあるのは正常。

実装: `PaidLeaveV2SummaryService::buildSummary()`（消滅日数）、
`PaidLeaveV2SummaryService::historySortDate()`（履歴の並び順、付与行は付与日・使用行は使用日）

## 触らないこと

- 有休対象外の人へ自動付与しない。
- 過去の使用日や残日数を表示都合で消さない。
- 給与側だけで有休残を補正しない。
