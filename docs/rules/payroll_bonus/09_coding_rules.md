# 実装ルール

## 目的

給与・賞与を今後改修するときに、同じ事故を繰り返さないための実装ルール。

## 基本ルール

- 日本語ラベル、日本語説明文を壊さない。
- 一括置換で日本語を直さない。
- 文字化けしたら、推測修正せず正しい元テキストを確認する。
- Access時代に一致確認済みの計算は、理由なく変更しない。
- 計算式を複数箇所に作らない。
- 同じ意味の合計は共通Serviceへ寄せる。
- 帳票側で計算しない。
- 表示だけの修正でDB値を変えない。
- 古いコードを残す場合は理由を書く。理由がない古いコードは削除する。

## 修正前に確認すること

1. どの画面の問題か。
2. どのボタン、どの帳票、どの年月、どのスタッフで起きたか。
3. DBの保存値が正しいか。
4. 表示だけが違うのか、保存値が違うのか。
5. 給与、賞与、賃金台帳、明細、振込一覧のどこまで影響するか。

## 修正の進め方

1. Viewで表示だけ直せるか確認する。
2. Controllerで渡している値が正しいか確認する。
3. Serviceの計算元と保存値を確認する。
4. 共通Serviceへ寄せられるか確認する。
5. DBカラム変更が必要か最後に判断する。

## 保存ボタンのルール

- 保存ボタンは手入力値を保存する。
- 保存ボタンで給与マスタを勝手に再取込しない。
- 保存ボタンで支給合計、控除合計、差引支給額などの合計値は再計算してよい。
- 手入力の歩合手当、調整手当、調整控除などを消さない。

## 個別計算ボタンのルール

- 雇用保険ボタンは雇用保険だけを計算する。
- 所得税ボタンは所得税だけを計算する。
- 社保ボタンは社保だけを計算する。
- 往診手当ボタンは往診手当、管理手当に関係する処理だけを行う。
- 個別ボタンで給与マスタを再取込しない。
- 個別ボタンで関係ない手入力欄を上書きしない。

## CSSルール

- 全ページ共通は `app-ui.css`。
- 管理画面の枠は `app-frame.css`。
- 給与・賞与だけで共通するものは `payroll.css`。
- そのページだけの微調整はBlade内の `<style>` でもよい。
- 同じ見た目を複数ページで使い始めたら、共通CSSへ移す。

## DBカラム変更ルール

- 使わない可能性があるカラムは、いきなり削除しない。
- まず `x_` を先頭につけて退避する。
- コード内検索で参照がないことを確認する。
- 実運用でエラーが出ないことを確認してから削除する。
- ラベル変更だけで済む場合はカラム名を変えない。

## ドキュメント更新ルール

- ルールが間違っていた場合、本文は正しいルールで上書きする。
- 間違ったルールを本文に残さない。
- 変更理由だけ `12_change_log.md` に短く残す。
- 検証した年月、スタッフ、金額は `20_validation_cases.md` に残す。
