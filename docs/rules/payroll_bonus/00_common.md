# 給与・賞与 共通ルール

## 目的

給与計算、賞与計算、帳票、明細の改修時に、Access運用時と違う計算や、給与と賞与で別々の式が混ざることを防ぐ。

このフォルダのルールは、給与・賞与まわりを触る前に必ず確認する。

## 基本方針

- 同じ意味の計算式を複数箇所に作らない。
- 支給合計、課税支給合計、非課税支給合計、社保合計、控除合計は `PayrollV2UpdateService` を正本にする。
- 給与と賞与で同じ合計計算を使えるものは同じ処理を使う。
- 手入力された値は、保存時に勝手に給与マスタへ戻さない。
- 再計算ボタン、個別計算ボタン、保存ボタンの意味を混ぜない。
- 業務委託は、雇用保険、社会保険、所得税、住民税、労災など社員向け控除・税・社保計算を走らせない。
- Access時代の運用と違う計算にする場合は、事前に理由を明記して相談する。

## CSSの置き場所

- 全ページ共通: `public/css/admin_v2/app-ui.css`
- 全ページ共通の外枠・ナビ: `public/css/admin_v2/app-frame.css`
- 給与・賞与だけの共通CSS: `public/css/admin_v2/payroll.css`
- そのページ専用の微調整: 各Blade内の `<style>`

給与・賞与だけで共通化するものを `app-ui.css` に上げない。ほかの画面へ影響するため。

## 旧カラムの扱い

- すぐ削除しない。
- 使わない候補はDB上で `x_` を頭につけて退避する。
- Laravelコードからは `x_` カラムを参照しない。
- 運用でエラーが出ないことを確認してから削除する。

## 退避済カラム

給与DB:

- `officer_com` -> `x_officer_com`
- `allowance_2` -> `x_allowance_2`

レセDB:

- `department_no_old` -> `x_department_no_old`
- `staff_name_old` -> `x_staff_name_old`

## 改修前チェック

- 変更対象は給与だけか、賞与にも影響するか。
- 同じ計算が既に `PayrollV2UpdateService` にないか。
- Access時代の計算根拠と違わないか。
- 手入力値を上書きしないか。
- `x_` カラムを参照していないか。
- DBカラム名の似た名前に注意する。

## 改修後チェック

- `php -l` で触ったPHPの構文確認をする。
- Bladeを触った場合は `php artisan view:cache` を通す。
- 給与計算ページ、賞与計算ページ、明細、賃金台帳のいずれかに影響がある場合は表示確認する。
- 計算を触った場合は `20_validation_cases.md` の検証ケースへ追記する。
